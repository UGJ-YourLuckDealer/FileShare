개발 역할 분담 제안 v3 (2026-11-07, 기능 위주)

※ 기능 목록은 기획 문서 PDF와 키링 제작 시스템 PDF에서 가져왔습니다.
※ 누가 어떤 기능을 맡을지는 기획서에 없는 제안입니다. 최종 분담은 팀 논의로 정합니다.
※ UI는 와이어프레임과 초기 디자인이 나온 뒤에 나누기로 해서 이번 분담에서는 뺐습니다. 기능은 임시 UI(버튼, 텍스트)로 확인합니다.
※ v3 변경: 판정 로직을 팀원 담당에서 hermit 담당으로 옮김 (hermit 결정)

[hermit - 게임 전체 틀 + 돈 + 판정]
1. 게임 흐름(하루 사이클): 쉬는 시간 시작 > 손님 > 제작 > 검사 > 하루 끝 > 다음 날로 넘어가는 상태 전환, 씬 전환, 일차 카운트
2. 자본 시스템: 판매가 선지급, 재료비 차감, 팁/환불 반영
3. 판정 로직: 구현비율 = (일치 개수 - 불일치 개수) / 총 개수 (PDF 원본에서 확인 필요)
   - 100%: 판매가 + 팁 10%
   - 80% 이상: 판매가만
   - 80% 미만이거나 0으로 나누는 경우: 환불
4. 승리/패배 판정: 7일차(임시) 도달 시 자본 >= 0이면 승리, 하루 끝 자본 < 0이면 게임 오버
5. 업그레이드 효과 적용 구조: 구매, 효과 반영 (목록은 TBD, 기획서 예시는 테이블/서머 타임/사탕 분류)
6. 공통 데이터 규칙과 연결 규칙: 재료/레시피/손님 데이터 형식, 팀원 작업을 붙이는 방법

[다른 개발 팀원 - 키링 제작 + 손님]
1. 재료/레시피 데이터 입력: 메인 재료(일반, 하트, 키링당 1개), 부재료(네잎 클로버, 4분음표, 숫자 7, 무지개, 여러 개 가능), 재료비 $1/판매가 $3 변수, 숫자 4와 7 레시피
2. 키링 제작 로직: 드래그앤드롭으로 재료 달기/빼기, 메인 1:1 제한, 재료를 쓸 때 자본 시스템에 차감 요청
3. 손님 시스템: 손님 데이터(행운의 숫자, 힌트 텍스트), 손님 등장 순서
4. 대화 진행 로직: 힌트 텍스트 출력, 일부 단어 색 강조

[나누는 기준]
hermit은 "하루가 굴러가고 돈과 판정이 맞는지", 팀원은 "손님을 받아 키링을 만드는 과정"을 맡습니다.
둘이 만나는 지점은 세 가지입니다.
- 서빙 시 제작된 키링 정보 전달 (어떤 재료가 몇 개 달렸는지) > hermit 판정
- 재료 사용 시 재료비 차감 요청
- 손님 1명 처리가 끝났다는 신호
이 세 가지만 먼저 정하면 각자 따로 만들 수 있습니다.
